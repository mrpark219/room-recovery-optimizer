# Room Recovery Optimizer

> **객실 이용 불가 상황 발생 시, 확정 예약을 최대한 유지하고 추가 운영 비용을 최소화하는 재배정 최적화 도구**

---

## 1. 문제 정의 및 배경

### 📌 어떤 문제인가?

숙박 운영 현장에서는 설비 고장, 누수, 긴급 점검 등으로 이미 예약된 객실을 정상 제공하지 못하는 객실 이용 불가 상황이 발생합니다.

### ❓ 왜 이것이 중요한가?

1. **신속한 대응:** 당일 발생한 돌발 상황에 대해 현장에서 빠르게 대안을 찾아 피해를 수습해야 한다.
2. **운영 비용 최소화:** 주먹구구식 대처로 비싼 객실을 배정하거나 불필요한 보상 비용이 발생하는 것을 막아야 한다.
3. **브랜드 신뢰 유지:** 일방적인 예약 취소를 최소화하여 고객 경험을 지키고 브랜드 신뢰도를 유지해야 한다.

### 🎯 목표

여러 예약의 조건과 가용 객실을 다차원 제약 조건으로 탐색하여, "최대 수용 + 최소 추가 비용"을 만족하는 최적의 재배정 계획을 도출합니다.

---

## 2. 구현

- 객실 이용 불가 기간을 등록하면, 서버가 해당 숙소의 예약과 객실 배정 현황을 조회해 영향받는 예약과 재배정 후보를 계산합니다.
- 예약 정보에는 고객이 선택한 **객실 유형**을 저장하고, 실제 물리 객실은 숙박 구간별로 별도 배정합니다.
- 객실 유형만 예약하고 실제 객실을 아직 배정받지 못한 확정 예약도 가용 객실을 두고 경쟁하므로 함께 계산합니다.

### 재배정 조건

1. **기간 산정:** 체크인 전 예약은 전체 숙박 기간을, 투숙 중인 예약은 남은 숙박일만 계산한다.
2. **조건 충족:** 예약 인원, 예약 유형 이상의 등급을 만족해야 한다. 장애 기간과 기존 점유 상태를 피해 같은 객실을 같은 날짜에 중복 배정하지 않는다.
3. **이동 동의:** 기본 원칙은 한 객실에서의 연속 숙박이다. 체크인 전 예약을 두 객실로 나누거나 투숙 중인 고객을 현재 객실에서 이동시킬 때는 제안한 이동 날짜에 대한 고객 동의가 필요하다.

### 배정 우선순위 및 동의 확인 추천

배정안은 다음 순서에 따라 비교하여 최적의 안을 도출한다.

1. 현재 객실을 사용할 수 없는 투숙객 수용
2. 전체 수용 건수 극대화
3. 예상 추가 비용 최소화
4. 객실 이동 횟수 최소화

- 예상 추가 비용은 재배정된 객실 유형의 기준가를 합산한 뒤, 동일한 숙박일수에 대한 기존 예약 유형의 기준가를 차감하여 산출한다.
    - 상위 등급 객실로만 재배정하므로 기준가 차액은 항상 0 이상이며, 별도의 직접
      보상비나 정비비는 산정 범위에서 제외한다.
- 서버는 **이미 확인된 동의만 반영한 안**과 **추가 동의를 확보했을 때 가능한 안**을 비교하여, 다음에 **동의를 확인해야 할 우선 대상 고객과 이유**를 안내한다.
    - 운영자가 통화 후 동의, 거절, 부재 상태를 입력할 때마다 최적안을 실시간으로 재계산한다.

---

## 3. 검증 방법

- 예약 접수순으로 배정하는 기준선과 전체 조합 탐색을 **동일한 입력, 제약, 우선순위** 조건에서 비교한다.
- 수용 건수와 제약 위반 여부를 확인하고, 같은 예약 집합을 수용한 경우에만 예상 비용 차이를 비교한다.

---

## 4. Docker로 실행

```bash
docker compose up --build --wait
```

이미지를 먼저 빌드한 후 실행할 수도 있습니다.

```bash
./scripts/build-images.sh
docker compose up --no-build --wait
```

- 프런트엔드는 [http://localhost:3000](http://localhost:3000), 백엔드
  API는 [http://localhost:8080/api/accommodations](http://localhost:8080/api/accommodations)에서 확인할 수 있습니다.
- MySQL은 로컬 3307 포트에 연결됩니다. 기본 프로필은 데모 데이터를 사용하는 `demo`입니다.
- `docker compose down`은 컨테이너와 네트워크를 중지·삭제하지만 MySQL 볼륨은 유지합니다.
- 데이터를 초기화하려면 `docker compose down -v`를 실행하세요.
